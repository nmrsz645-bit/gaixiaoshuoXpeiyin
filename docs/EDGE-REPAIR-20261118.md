# Edge 配音修复测试记录

2026-11-18，北京时间。分支 `codex/edge-repair-20261118`，候选版本 `1.0.32-edge-test.1`。

## 故障依据

故障电脑在同一网络上，15:49 使用 Edge 7.2.5 成功生成晓晓、云希短句。15:59 的后续工具在音色列表请求阶段收到 429，晓伊、晓晓合成均跳过。原软件固定晓晓、默认参数时也报告过 NoAudioReceived。后者表示连接后未收到有效音频，现有资料尚不能确认两种症状同因。

## 修复内容

- Edge 依赖升级到官方固定版 7.3.1，采用其新版服务地址、v2 鉴权和不受中文区域设置影响的日期解析。来源为 [上游发布](https://github.com/rany2/edge-tts/releases/tag/7.3.1) 和 [v2 鉴权修复](https://github.com/rany2/edge-tts/pull/492)。PyPI wheel SHA-256 为 `2a3c79d6235a7a736d681233823ce5492e829b43eb47beae49aa181237a8f9a4`。
- 新配置默认 Edge，开启晓伊、晓晓随机选择。每本在开始合成时选一次，重试沿用同一音色。已有明确配置继续保留。界面保存的有效随机名单优先于旧编号文件，旧文件保留。
- GUI 与后台配音共用一个跨线程 Edge 请求门控。429 优先读取 Retry-After，缺失时采用本地五分钟冷却策略。冷却中的 Edge 任务在领取前等待。
- NoAudioReceived 作为暂时故障自动重试，耗尽当轮重试后短暂暂停 Edge。它不会增加业务终止失败次数。原文、配音回执与进度保留。
- “仅测试 Edge”使用当前界面中的 Edge 字段、独立临时文件及真实重试路径，并报告选中的音色和耗时。这个按钮只请求 Edge。与“测试全部接口”共用运行中标记，防止重复点击。
- 保存时检查语速、音调、音量的符号及单位，避免再次保存 `+30` 这种缺少单位的格式。

## 验证

Python 3.13.15，按 requirements-windows-verified.txt 安装独立环境。`pip check` 通过，`run_tests.bat` 共 432 项离线测试通过。新增检查覆盖 429 等待、跨线程互斥、同音色重试、无音频多轮后的 TXT 和回执保留、随机名单以及独立按钮调用边界。

本机新依赖直接合成测试中，两个音色对“接口测试”和参考样音各成功一次，四次连接均返回 HTTP 101。随后两个音色分别合成同一篇原创完整测试小说，6746 个非空白字符（含标点），各六次连接均成功。晓伊约 133.2 秒、晓晓约 132.1 秒，整篇 MP3 均通过严格解码。这些长文本验证使用的重试次数为零。

应用已重新打包。空白隔离目录启动时窗口标题正确，首次配置默认 Edge、晓伊及晓晓随机。Windows 捕获工具两次超时，因此本轮没有取得可用界面截图或通过视觉方式确认按钮位置。按钮的独立调用边界已有自动回归覆盖。

独立 Edge 修复验证工具使用同一新版依赖，直接测试两个固定音色，不请求音色列表。该工具通过九项本地模拟检查、冻结自检、无 Python PATH 解压自检和启动入口检查。

## LuxTTS 对应音色试听

另一个隔离原型位于 `C:\Projects\novel-luxtts-edge-voices-20261118`，默认只从晓伊、晓晓两个参考配置随机选择一次。各配置使用对应 Edge 音色生成的五秒 WAV，指纹分别校验。
